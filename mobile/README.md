# TenTen for iPhone (Expo)

The native iPhone app — currently the **camera trial** build
(`docs/iphone-app.md` §19). TypeScript end to end; built in Expo's cloud
(EAS), so no Mac is needed.

## What it does (structure build, v0.2.0)

Five tabs — **Today · Collection · ◉ Camera · Rate · More** — on Expo Router
(`src/app/`):

- **Camera** (the raised centre button): Identify from the viewfinder via
  `POST /api/identify`, then **Photograph** a match. Shoot-after-shoot with
  lens stops (0.5× / 1× / tele), tap-to-focus, the triple camera's automatic
  macro switch-over, a Photo Lab angle chip per frame, and a **live dial
  sharpness meter** (`src/lib/focus.ts`, a VisionCamera frame processor —
  the raw number is shown while its threshold is calibrated). Frames upload
  in the background at 2000px through `POST /api/watches/:id/photos`, each
  with an Undo; Done warns about frames still uploading or failed.
- **Collection**: the photo grid with search → a minimal watch page with
  "Photograph this watch".
- **Today** and **Rate**: placeholders. Next release: Add a watch + wear
  logging together.
- **More**: Face ID lock (optional), version / updates, open the web app,
  Sign out (behind a confirmation).
- Sign-in once per install (Stack.Protected); the session persists.

## Builds vs over-the-air updates

`runtimeVersion` follows the app `version`. JavaScript-only changes ship with
`eas update --channel preview` and reach the phone on next launch ("An update
is ready · Restart"). Anything that adds a native module or permission needs
a new build — **and a version bump**, so updates for it can never land on an
older build that lacks the native code. The exact update command is:

```bash
npx eas-cli update --channel preview --environment production --platform ios --message "..." --non-interactive
```

`--environment production` is not a typo: the preview BUILD profile reads its
variables from the production environment (eas.json), and that is the only
environment holding the Supabase settings. `--environment preview` publishes a
bundle with no Supabase URL/key — the phone drops to sign-in with "This build
is missing its Supabase settings" (v1.11.20). Check the CLI's first line names
both `EXPO_PUBLIC_SUPABASE_*` variables before trusting a publish.
`--platform ios` because the app has no web target (the default `all` fails
on react-native-web). v0.2.0 pre-installs every native
package v1 is expected to need (router, gestures, reanimated, worklets, svg,
netinfo, image picker) so the next features can ship as updates.

`.easignore` (repo root) keeps the upload to the app and `src/lib`. EAS reads
it from the git root and tests paths without trailing slashes — write plain
excludes, not a "/*" + "!/mobile/" whitelist (that produced an 80-byte
archive).

## How it connects

- Reads go straight to Supabase as the signed-in user (RLS).
- Uploads, deletes and Identify go to the deployed web app's `/api` routes with
  `Authorization: Bearer <token>` (`getRequestAuth` on the server). **The web
  app must be deployed with v1.11.3+** for those routes to exist.
- Pure web files (`src/lib/photo-lab.ts`, `validations/*`, …) are imported
  directly via `@/lib/...` — see `metro.config.js`. Never copy them here.

## Configuration (EAS environment variables — never committed)

| Name | Value |
|---|---|
| `EXPO_PUBLIC_SUPABASE_URL` | Supabase → Project Settings → API → Project URL |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Same page → the `anon` / publishable key (public by design) |
| `EXPO_PUBLIC_API_BASE` | Optional; defaults to `https://caliber-shelf.vercel.app` |

## Commands

```bash
npm run typecheck        # tsc over the app and the shared web files
npm run doctor           # expo-doctor
npx expo export --platform ios   # bundle check without a build
npx eas-cli@latest build --profile preview --platform ios
```

`ios/` and `android/` are generated by EAS (Continuous Native Generation) —
never create or edit them; configure native behaviour in `app.json`.
